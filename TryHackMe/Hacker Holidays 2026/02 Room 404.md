### Recon
We start with an Nmap scan, like always. I wonder what we'll find there..
```
root@ip-10-114-111-58:~# nmap -sS 10.114.175.245 -p- -n -Pn -v
...
PORT     STATE SERVICE
22/tcp   open  ssh
8080/tcp open  http-proxy
```

> Ah, so the HTTP server is not on the default 80 port, but an alternative one: 8080. Good to know that there are no hidden services.

Quick note:
- `-sS`: Half-Open SYN Scan, [the default one](https://nmap.org/book/synscan.html). We don't care about being noisy.
- `-p-`: scan all 65535 ports
- `-n`: do not use reverse DNS in order to resolve the IP to any domain name
- `-Pn`: assume that the server is UP and proceed with the scan
- `-v`: verbose output (cut down for brewity in this writeup)

Let us look closer:
```
root@ip-10-114-111-58:~# nmap -sC -sV -O 10.114.175.245 -p22,8080 -n -Pn -v
...

Git repository found! So that's where the flag is ;)

### The Git Repository
When we go to the `/.git/` folder (`10.114.175.245:8080/.git/`), we can see it's accessible. Sadly, the contents and folders are locked (Directory listing is OFF). We need to bruteforce.

### Bruteforce the Git repo
On the internet I quickly found [GitHacker](https://github.com/wangyihang/githacker) - a simple tool for git repository enumeration
```
root@ip-10-114-111-58:/githacker# pip install GitHacker
Collecting GitHacker
```

```
root@ip-10-114-111-58:/githacker# githacker --brute --url http://10.114.175.245:8080/ --output-folder result
